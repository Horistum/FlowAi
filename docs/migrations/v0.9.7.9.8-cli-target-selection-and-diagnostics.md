# Migration: v0.9.7.9.8 CLI Target Selection and Diagnostics

## Affected users

This migration applies to scripts and operators that invoke the Flow CLI through the Gradle application entrypoint.

## Target selection is now explicit

Previous behavior selected Jenkins when `--target` was omitted from `intent` or lowered `normalize` commands.

New behavior preserves target neutrality:

```bash
./gradlew run --args="intent examples/intent/build-test-deploy.intent.yaml"
```

This emits planning, negotiation and selection evidence but does not create a target manifest.

To request target-specific evidence, supply the target explicitly:

```bash
./gradlew run --args="intent examples/intent/build-test-deploy.intent.yaml --target jenkins"
```

To request rendered target syntax, supply both target and render intent:

```bash
./gradlew run --args="intent examples/intent/build-test-deploy.intent.yaml --target jenkins --render"
```

`--render` without `--target` is invalid.

## Review-only and blocked outcomes

Expected target incompatibility no longer terminates with an uncaught materialization exception. The CLI emits:

- `cli-target-outcome.json`;
- reconciled compatibility, negotiation, readiness, selection and trace reports;
- `target-manifest.json` containing diagnostic evidence when structurally valid;
- `target-render-readiness.json`.

No target syntax is emitted unless the outcome is `EXECUTABLE`.

A requested render that is review-only or blocked returns exit status `3`. Review artifacts may still be written to `--out` so automation can archive and inspect the evidence.

## Unknown commands

The legacy CLI fallback has been removed. Commands must be one of the documented explicit commands. Unknown commands return exit status `2` and a structured `CLI DIAGNOSTIC FAILURE` report.

The former implicit invocation:

```bash
./gradlew run --args="examples/hello.flow"
```

must become:

```bash
./gradlew run --args="flow examples/hello.flow"
```

The `flow` command remains target-neutral and prints registry-derived negotiation evidence rather than generating a hardcoded list of target manifests.

## Automation guidance

Automation should distinguish:

- exit `0`: requested diagnostic or executable action completed;
- exit `2`: invalid command input or integrity failure;
- exit `3`: target-specific strict or render action was not executable.

Do not infer executability from the existence of `target-manifest.json`. Read `cli-target-outcome.json` and `target-render-readiness.json`.
