# v0.9.3 Capability Degradation Semantics

## Summary

v0.9.3 adds explicit capability degradation semantics over `TargetManifest` outputs.

The release introduces a degradation analyzer that classifies target behavior as supported, degraded or blocked and explains what is preserved, approximated and blocked.

## Added

- `TargetCapabilityDegradationAnalyzer`
- `TargetCapabilityDegradationReport`
- `TargetCapabilityDegradationEntry`
- `TargetCapabilityDegradationStatus`
- `TargetCapabilityDegradationAnalyzerTests`
- `docs/V0_9_3_CAPABILITY_DEGRADATION_SEMANTICS.md`

## Behavior

The analyzer collects degradation information from:

- manifest mapping notes
- job mapping notes
- step mapping notes
- `supportLevel=partial` metadata

It produces:

- `SUPPORTED` when no degradation entries exist
- `DEGRADED` when approximate or review-required semantics exist
- `BLOCKED` when a feature has no safe target-side preservation guarantee

## Strict mode

Standard mode allows degraded reports for review but rejects blocked reports.

Strict mode rejects both degraded and blocked reports before rendering.

## Validation expectation

GitHub Actions or local review must run:

```bash
./gradlew --no-daemon clean test --stacktrace --console=plain
./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain
```
