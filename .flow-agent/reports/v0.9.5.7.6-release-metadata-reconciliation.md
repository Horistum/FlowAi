# v0.9.5.7.6 Release Metadata Reconciliation

## Purpose

Reconcile the package line, correction-track scope, changelog, report and roadmap metadata without confusing an internal correction item with a published package, public standard or artifact contract version.

## Outcome

The repository now exposes one explicit version boundary:

- published package: `0.9.4`
- unreleased correction track: `v0.9.5.x`
- current correction item: `0.9.5.7.6`
- next correction item: `0.9.5.7.7`
- next expected package: `0.9.5`
- active public standard: `0.7.6`
- artifact contract versions: unchanged

A correction item is not treated as a package, public-standard, schema or conformance-gate version.

## Implemented changes

- recorded the v0.9.5.x correction track in `CHANGELOG.md`
- aligned `build.gradle.kts`, `REPORT.md`, release state, the main roadmap, the repair roadmap and versioning policy
- documented the package/correction/public-standard/artifact-contract boundaries
- replaced future-roadmap version scheduling in `CiCdBiasInventoryAnalyzer` with evidence-driven architectural follow-up areas
- added regression coverage for analyzer follow-up classification and release metadata consistency
- added shared Flow Agent roadmap resolution for the main roadmap and its declared active repair track
- required exactly one `status: next` item across active roadmap sources
- rejected missing, ambiguous, self-referencing and repository-external active roadmap declarations
- included the active repair roadmap in generated Flow Agent context
- added Python unit tests for Flow Agent roadmap resolution and wired them into standard CI

## Validation

The standard Flow CI completed successfully on the pull request branch with:

- Flow Agent roadmap tooling unit tests
- Flow Agent structure validation
- Flow Agent context generation
- cache-aware offline test and conformance checks
- `./gradlew --no-daemon clean test --stacktrace --console=plain`
- `./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain`
- CI log and test-report artifact publication

No validation gate was weakened or bypassed. The initial Flow Agent failure exposed that the validator and context generator only inspected the main roadmap. The fix follows the declared active repair track instead of falsely promoting umbrella item `0.9.5.8` to `next`.

## Architecture boundary

This work is release metadata and analyzer-input reconciliation. It does not add runtime execution, an SDK, a framework lifecycle, shell projection, target-specific public syntax or renderer payload implementations.
