# v0.9.5.7.3 Renderer Failure Semantics Unification

## Summary

v0.9.5.7.3 introduces a shared renderer-readiness policy for Jenkins, GitHub Actions and Tekton.

Unresolved materialization is now rejected before target serialization instead of being represented as a fail-later Jenkins pipeline, a green GitHub Actions no-op, or a Tekton phantom Task dependency.

## Added

- `TargetRenderMode`
- `TargetRenderReadiness`
- `TargetRendererReadinessAnalyzer`
- `TargetManifestNotExecutableException`

## Changed

- `TargetRendererContractValidator` now separates structural validity from executable readiness.
- `requireRenderable()` raises one typed readiness exception for structurally valid but unresolved manifests.
- Projection smoke tests now assert fail-before-serialization behavior for all three renderers.

## Readiness rule

An actionable step is executable only when it has:

- `TargetMaterializationStatus.NATIVE`
- projection artifact evidence `TARGET_NATIVE`

Notes-backed, adapter-required, declarative-only, semantic-only, unsupported and blocked work does not pass executable target serialization.

## Correction result

The renderer layer no longer serializes target syntax when required semantic actions remain unresolved. This removes target-specific placebo and phantom failure mechanisms while preserving materialization evidence in `TargetManifest`.
