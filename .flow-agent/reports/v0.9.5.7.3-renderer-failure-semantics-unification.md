# v0.9.5.7.3 Renderer Failure Semantics Unification

## Summary

v0.9.5.7.3 introduces a shared renderer-readiness policy for Jenkins, GitHub Actions and Tekton.

Unresolved materialization is now represented by one deterministic non-executable review artifact instead of a fail-later Jenkins pipeline, a green GitHub Actions no-op, or a Tekton phantom Task dependency.

## Added

- `TargetRenderMode`
- `TargetRenderReadiness`
- `TargetRendererReadinessAnalyzer`
- `TargetReviewArtifactRenderer`

## Changed

- `TargetRendererContractValidator` now separates structural validity from executable readiness.
- Structurally valid unresolved manifests carry a `TARGET_ARTIFACT_REVIEW_ONLY` warning.
- All three renderers emit the same comment-only review artifact before target syntax.
- Projection smoke tests assert that unresolved rendering contains no Jenkins, GitHub Actions or Tekton executable syntax.

## Readiness rule

An actionable step is executable only when it has:

- `TargetMaterializationStatus.NATIVE`
- projection artifact evidence `TARGET_NATIVE`

Notes-backed, adapter-required, declarative-only, semantic-only, unsupported and blocked work does not pass executable target serialization.

## Correction result

The renderer layer no longer serializes target syntax when required semantic actions remain unresolved. It preserves audit evidence without producing green no-op jobs, phantom dependencies or fail-later pipelines.
