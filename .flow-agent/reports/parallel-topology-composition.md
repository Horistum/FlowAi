# AR-06AE-C7 — Parallel branch topology composition

Based on merged PR #234, `b1f54f16a10e5701e6954677d9bed5c91179b25d`.

## Architectural correction

The previous resolver and renderer recognized one group containing exactly two
manual approvals, optionally followed by one checkout each. Distinct messages and
uniform body shape were required. Those properties described the test fixture rather
than branch isolation or fork/join semantics.

Eligibility now follows preserved branch membership, local sequential dependencies
and adapter-owned native isolation mappings. Multiple top-level groups, arbitrary
nonzero branch counts, empty branches, repeated messages/labels, mixed leaf sequences
and unused checkout result aliases are composable. Native closure keys and directory
paths use preserved identities, never authored display labels or approval text.

The native input mapping is control-local. Parallel inputs receive `Flow_<step-id>`
routing IDs independent of their messages. The pinned input plugin otherwise hashes
the message into its ID, and `InputAction.getDynamic(token)` routes to the first
matching execution. Removing distinct-message eligibility without changing this
mapping would make UI/API decisions ambiguous even when direct execution-object
calls pass. The observer now uses that same native ID lookup, records requested and
resolved identities, and rejects a mutant that restores message-derived IDs.

The explicit prefix prevents the plugin's first-character capitalization from
collapsing distinct native step IDs; unsupported URL identities fail rendering.

The full-history literal-branch git mapping
is workspace-local; consecutive workspace operations share their branch directory,
and later segments return to it. The renderer does not infer that a directory isolates
a shared service such as a Docker daemon. Leaf type support and native isolation are
separate contracts. Other checkout modes remain bounded by their own missing topology
evidence, rather than a whole-workflow matcher.

Only top-level groups and sequential leaves are included. Other control nesting,
cross-branch dependencies, branch state/value/workspace transfer, fresh-workspace and
security isolation require separate contracts and evidence. Existing independent
leaf materialization, value scope, continuity and provider checks remain mandatory.
Caller-supplied manifests recheck the same native isolation and branch-local ordering.
Historical pair-of-gates rendering retains its branch/workspace layout; parallel
approvals now carry explicit routing IDs.
Core meaning, public syntax/schema/version and target-wide support are unchanged.

The first native run exposed an observation-timing defect: a later root checkout can
remove completed branch directories. Physical effects are therefore captured in SCM
callbacks at checkout completion and matched by branch directory and sequential
occurrence. Final directory contents remain diagnostic and are not used to infer
post-join durability. Native revisions must match the independently prepared fixture
refs. This corrects the observer without changing product behavior or weakening join,
workspace ownership, ordering or failure checks.

## Independent verification

Source-frontend projection tests vary group/branch/body counts, positions, aliases,
labels and messages. They include empty and heterogeneous branches, local dependency
acceptance, crossing dependency rejection, unsupported shared-service isolation,
forged directory identities, payload substitutions and hidden children.

A verification-only source model binds canonical roots, branch membership, policies,
parameters and manifest leaves. Native input and git calls are wrapped in observation
stages that restore original generated bytes exactly. The disposable observer records
pending input identities, native branch and group intervals, per-branch order, actual
dir arguments, checkout arguments, SCM-callback physical markers and revisions, native
error causes and terminal error origin. It routes declared input IDs through the native UI/API lookup without
receiving expected outcomes. No expected total order is imposed on sibling branches.

Six baselines cover successful join, checkout failure and rejection with both failFast
policies. Nine mutants serialize branches, omit or reorder work, alias directories,
run successors early, swallow failures, disable cancellation or alias approval routing IDs. A deterministic local
Git repository and a network-disabled container keep branch effects independently
observable without external repository availability. Source/artifact/observation/log
receipts bind the evidence to its exact CI revision and run.

This is separate composition regression evidence, not signed-portfolio expansion.
All 39 historical assessments and existing native/composition checks remain required.
Exact-head and synthetic-merge compilation, tests, conformance, Flow Agent validation
and physical module isolation must pass. Final observed receipts belong in the PR;
this report does not preclaim CI results. Local Python tests are distinct from the
pinned JDK 25 / Kotlin 2.4.10 / Gradle 9.5 native and JVM validation environment.
