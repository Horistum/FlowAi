# v0.9.5.7 Target Registry Honesty

## Summary

v0.9.5.7 adds an honest target registry support model.

The registry now separates declared target names from experimental, implemented, tested, production-supported, deprecated and blocked targets.

## Added

- `TargetRegistryStatus`
- `TargetRegistryEvidenceKind`
- `TargetRegistryEvidence`
- `TargetRegistryEntry`
- `TargetRegistrySnapshot`
- `TargetRegistryHonestyValidator`
- `StandardTargetRegistryHonestySnapshots.baseline()`
- `FlowTargetRegistryHonestyTests`
- `docs/V0_9_5_7_TARGET_REGISTRY_HONESTY.md`

## Correction result

Target names are no longer enough to imply support. Production support now requires implementation, projection, test, conformance and capability evidence.

The baseline registry marks Jenkins, GitHub Actions and Tekton as tested rather than production-supported. Shell is retained only as blocked registry evidence.

## Validation focus

The tests cover support inflation, premature declared-only evidence, shell-like target blocking, status-specific evidence requirements and forbidden implicit support wording.

## Versioning boundary

- Current package version remains `0.9.4`.
- Active public standard version remains `0.7.6`.
- No artifact schema version is changed.
