# Flow Core v0.7.6 Release Report

## Objective

v0.7.6 is a semantic correctness hardening release on top of v0.7.5.

The release fixes concrete defects in intent lowering, target rendering, validation scope handling, interpolation, safety enforcement and rendered snapshot consistency while preserving Flow's primary purpose:

> Flow is an AI-first standardization layer for IT and DevOps automation intent.

## Scope

Included:

- Kubernetes deploy lowering preserves the intent application identity instead of falling back to a literal placeholder.
- Runtime input references render as target-native parameters.
- Target parameter interpolation is centralized across generated command types.
- Mandatory high-risk capability safety enforcement is handled by the core intent validator.
- Validator block scoping works for sibling statements in conditional, parallel, match, try/retry and error-handler blocks.
- Mixed safe-navigation semantics are preserved per path segment.
- Single-quoted strings and exact interpolation references are handled correctly.
- Jenkins named-pattern rendering does not fall back to a match-everything regular expression.
- Rendered end-to-end snapshots remain exact.

Excluded:

- No runtime executor.
- No SDK API.
- No plugin lifecycle.
- No target-specific public DSL.
- No renderer expansion.
- No Flow syntax expansion.

## Architecture Compliance

The release remains inside the standardization-layer boundary.

It strengthens correctness of existing planning, validation and projection behavior, but it does not move workflow execution into Flow Core and does not introduce target-specific public syntax.
v0.7.6 closes the semantic correctness hardening release line.
