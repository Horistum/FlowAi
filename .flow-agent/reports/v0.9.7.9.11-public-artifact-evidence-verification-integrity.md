# v0.9.7.9.11 Public Artifact Evidence and Verification Integrity

## Status

The bounded correction is `active`. Parent Core item `0.9.7.9` is `correction-required`, and closure item `0.9.7.10` is `blocked`. No passing validation is claimed until the public pull-request head and its synthetic merge candidate independently pass Flow CI.

## Confirmed defects

1. Several public StandardSurface artifacts self-certified `status: PASS` rather than deriving status from validated content.
2. The public target-semantics matrix contained handwritten target mechanism claims that disagreed with provider-owned approval contracts.
3. Artifact producer provenance and introduced-version metadata used string tables with generic or fictional fallbacks.
4. Required artifact derivation accepted any non-empty `derivedFrom` value, including references to nonexistent artifacts.
5. Bundle verification searched JSON text for substrings instead of parsing authoritative fields and preserving failed conformance polarity.

## Implemented boundary

### Computed public report status

- `StandardSurfaceStatusAuthority` derives public surface, compatibility policy, reference corpus, reference harness, target semantics, export bundle, conformance levels and export manifest status from their content.
- Unit and standalone conformance supply explicit malformed or incomplete negative counterparts.
- Public reports no longer use a literal PASS as their own validation evidence.

### Provider-backed target semantics

- Target inventory comes from `TargetRegistryYamlLoader`.
- Condition support comes from `TargetExpressionSupport`.
- Approval support comes from provider-owned `TargetNativeApprovalProjectionDefinition` contracts.
- Secret and artifact support comes from typed native projection bindings.
- Missing provider evidence remains `adapter-required-review-only` or `not-declared-review-only`.
- Jenkins is the only built-in provider with native `approval.manual`; GitHub Actions and Tekton are review-only for that feature.

### Exact artifact contracts

- `ArtifactContractAuthority` owns stable producer ids and introduction metadata.
- Unknown non-rendered artifacts fail closed.
- Distribution-specific rendered files are authorized only through the typed `RENDERED` role.
- `ArtifactEvidenceAnalyzer` and `StandardContractIndexAnalyzer` consume the same authority.

### Derivation integrity

- Required derived artifacts must cite a declared artifact or registered external evidence source.
- Empty, dangling or duplicate evidence identities are reported as missing evidence.
- The public `evidence.complete` compliance gate fails when lineage is unresolved.

### Structured standard verification

- `StandardBundleVerifier` parses typed conformance and export bundle models.
- Unknown fields and duplicate JSON keys fail closed.
- Conformance requires the active standard version, PASS status, consistent totals, exact required-check membership and no required gate in `failedChecks`.
- Stable artifact coverage is evaluated only against `standard-export-bundle.requiredArtifacts`.
- A failed gate id in `failedChecks`, an unrelated textual mention or malformed JSON cannot satisfy verification.

## Version boundary

The implementation package remains `0.9.5`, the public standard remains `0.8.0`, and the artifact contract remains `2.0`.

## Validation boundary

The implementation head must independently pass:

- exact pull-request head Flow CI;
- synthetic merge-candidate Flow CI;
- Flow Agent tooling and repository structure;
- complete tests;
- standalone conformance.

After implementation evidence passes, completion metadata must be committed separately and the resulting head must pass the same two jobs before the pull request may become ready for review.
