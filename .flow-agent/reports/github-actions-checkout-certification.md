# AR-06M candidate: native GitHub Actions checkout

The second reference adapter now has an opt-in native-provider certification job.
The current compiler binds a public intent fixture, canonical graph and GitHub
Actions rendering. A checked observation envelope executes exactly its single
native checkout step on a GitHub-hosted runner, followed by omitted-checkout and
substituted-revision mutants. Independent Git HEAD and fixture-file SHA-256
observations must match separate immutable-revision oracles.

The observer and source snapshot are staged outside the runner workspace before
each workspace is cleared. Cleanup requires the exact authorized real directory,
rejects aliases and never follows child symlinks. The workflow actually selected
by GitHub must match the selected source workflow bytes, including on a PR merge
revision. Rendering changes that introduce extra jobs, steps, guards or bindings
are rejected rather than silently broadening the experiment.

Rendering inspection uses the shared strict `FlowYaml` boundary. The runtime job
first runs focused harness, YAML-owner and authority-catalog regressions, including
a fresh JVM with an empty working directory and Gradle's explicit test classpath.
This exposes integration failures before provider execution without replacing the
required complete exact-head and merge-candidate test suites.

The owner establishes an Ed25519 key and fresh challenge before native execution.
The exact three-run inventory is signed and admitted through the existing
compiler-bound certification contract. Evidence includes source, canonical graph,
rendered baseline/mutants, execution envelope, independent observations, public
trust, proof and diagnostic views. The private key is outside the uploaded artifact
and removed even on workflow failure.

This is a native-leaf claim. The generated workflow itself is not executed as a
whole. No scheduling, trigger, credentials, workspace-transfer or structural claim
is derived. The runner and action share the observation owner's trust boundary;
signatures do not protect against a compromised runner or action. The hosted image
and action reference are recorded, without claiming immutable provider binaries.
The existing ten-assessment Jenkins portfolio remains separately scoped; its
missing GitHub evidence rows describe that portfolio only.
