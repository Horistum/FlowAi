# v0.9.5.3 Notes Package Contract Model

## Summary

v0.9.5.3 adds the first explicit notes package contract model for the architecture recenter correction track.

The goal is to define the declaration boundary before later work moves semantics, materialization, target honesty, safety policy and trigger behavior into notes-driven layers.

## Added

- `NotesPackageKind`
- `NotesPackageDependency`
- `NotesPackageBoundary`
- `NotesPackageContract`
- `NotesPackageContractValidator`
- `StandardNotesPackageContracts`
- `FlowNotesPackageContractTests`
- `docs/V0_9_5_3_NOTES_PACKAGE_CONTRACT_MODEL.md`

## Contract boundaries

The contract model defines seven package kinds:

- `DOMAIN`
- `CAPABILITY`
- `SAFETY`
- `RUNTIME`
- `TARGET`
- `PROJECTION`
- `CONFORMANCE`

The validator prevents packages from claiming runtime execution, SDK APIs, plugin lifecycle, public DSLs, shell projection, command execution or target-specific semantic ownership.

## Correction result

The project now has a stable internal contract surface for notes packages. This does not load notes packages, execute them, materialize target work or expand the public standard schema. It only defines and tests the contract boundary.

## Versioning boundary

- Current package version remains `0.9.4`.
- Active public standard version remains `0.7.6`.
- No artifact schema version is changed.
- No runtime executor, SDK API, plugin lifecycle, target-specific public DSL, renderer expansion or Flow syntax change is introduced.
