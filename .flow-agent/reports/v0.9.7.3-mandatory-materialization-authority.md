# v0.9.7.3 Mandatory Materialization Authority

## Status

Completed.

## Objective

Make planning validation mandatory before projection so invalid planning evidence cannot reach an implementation boundary through any public path.

## Implemented authority

- one `MandatoryMaterializationAuthority` validates target-neutral execution-plan integrity and derives compatibility from the canonical target registry
- target generators consume an unforgeable projection authorization instead of caller-supplied compatibility evidence
- public manifest generation accepts only an execution plan, target identity and strictness request
- execution-candidate authorization fails before projection when capability constraints are not satisfied
- diagnostic-evidence authorization may preserve blocked target evidence, but it remains structurally validated, registry-derived and explicitly non-executable
- semantic graph, materialization negotiation, projection plan and artifact authority alignment are validated before resolved evidence is returned
- production conformance, reference snapshot and CLI composition paths route through the same authority
- the optional projection helper and duplicate planner capability gate were removed
- negative tests prove invalid plans do not invoke target generators and malformed materialization evidence fails closed

## Boundary

This work does not add target capability, runtime execution, implementation-specific syntax, or adapter-owned semantics. Package, public standard and artifact contract versions remain unchanged.
