# v0.9.4 Reference Scenario Matrix

## Summary

v0.9.4 adds a target-neutral reference scenario matrix before end-to-end readiness work.

The release introduces a declarative matrix covering common automation workflows, universal semantic capabilities, risk metadata, safety requirements and portability expectations. Concrete adapter expectations for Jenkins, GitHub Actions and Tekton are kept in a separate adapter projection matrix.

- `ReferenceScenarioMatrix`
- `ReferenceScenario`
- `ReferenceSemanticExpectation`
- `ReferencePortabilityClass`
- `ReferenceScenarioKind`
- `ReferenceScenarioRisk`
- `ReferenceAdapterProjectionMatrix`

- `ReferenceAdapterProjectionOutcome`

## Scenario coverage

The target-neutral matrix covers:

- build/test/deploy
- API sync
- database migration
- rollback workflow
- cleanup
- secret rotation
- notification workflow
- negative cleanup without approval

## Validation coverage

Positive core scenarios run through:

- parser
- Flow validator
- safety validator
- planner

Adapter projection checks are separated and run through:

- compatibility analysis
- target manifest generation
- degradation analysis

Negative scenarios are not skipped. They must parse and then fail at a core validation gate with explicit diagnostic codes. The rejecting gate may be the Flow validator or the safety boundary, depending on where the violation is detected first.

## Architecture correction

The release explicitly separates:

```text
ReferenceScenarioMatrix = target-neutral automation semantics
ReferenceAdapterProjectionMatrix = known target adapter projection expectations
```

Jenkins, GitHub Actions and Tekton are adapter targets. They are not the source of truth for reference scenario meaning.

## Validation expectation

GitHub Actions or local review must run:

```bash
./gradlew --no-daemon clean test --stacktrace --console=plain
./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain
```
