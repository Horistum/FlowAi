# v0.9.4 Reference Scenario Matrix

## Summary

v0.9.4 adds a reference scenario matrix before end-to-end readiness work.

The release introduces a declarative matrix covering common automation workflows, risk metadata, safety requirements and target expectations.

## Added

- `ReferenceScenarioMatrix`
- `ReferenceScenario`
- `ReferenceScenarioKind`
- `ReferenceScenarioRisk`
- `ReferenceTargetOutcome`
- `ReferenceTargetExpectation`
- `ReferenceScenarioMatrixTests`
- `docs/V0_9_4_REFERENCE_SCENARIO_MATRIX.md`

## Scenario coverage

The matrix covers:

- build/test/deploy
- API sync
- database migration
- rollback workflow
- cleanup
- secret rotation
- notification workflow
- negative cleanup without approval

## Validation coverage

Positive scenarios run through:

- parser
- Flow validator
- safety validator
- planner
- compatibility analysis
- target manifest generation
- manifest contract validation
- degradation analysis

Negative scenarios are not skipped. They must parse, validate structurally and then fail safety validation with explicit diagnostic codes.

## Validation expectation

GitHub Actions or local review must run:

```bash
./gradlew --no-daemon clean test --stacktrace --console=plain
./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain
```
