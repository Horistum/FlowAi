# v0.9.6.4 Native Projection Architecture Report

## Purpose

Prevent a declarative `NATIVE` target registry rule from being treated as implemented native projection coverage unless the selected target distribution owns a matching implementation contract.

## Architecture change

- Added an immutable target-neutral native projection catalog.
- Added opaque native projection definitions keyed by payload kind and reference.
- Added required/optional typed binding slot contracts.
- Moved native typed binding compilation out of the general materialization resolver and behind the catalog contract.
- Required reconciled generators and projection providers to validate native registry rules and generated manifest payloads.
- Preserved concrete syntax and handler behavior in edge renderers.

## Built-in evidence

The built-in distribution declares exactly the native coverage that already exists:

- Jenkins: `JENKINS_STEP/git` with typed `url` and `branch` task-parameter bindings.
- GitHub Actions: no native catalog entries in this work item.
- Tekton: no native catalog entries in this work item.

No new action is made executable by v0.9.6.4.

## Fail-closed behavior

Generation rejects:

- a native rule without a matching implementation definition;
- duplicate implementation identities;
- missing required bindings;
- unexpected bindings;
- binding kinds not accepted by the implementation contract;
- payloads or catalogs bound to another target;
- manifests containing native payloads not owned by the selected provider.

Missing compile-time values remain explicit `UNRESOLVED` bindings and therefore cannot silently become executable empty text.

## Tests

Coverage includes catalog uniqueness, target ownership, registry/catalog agreement, typed binding compilation, unresolved value preservation, fabricated GitHub Actions native coverage rejection, existing Jenkins checkout preservation and Core target-neutrality guards.
