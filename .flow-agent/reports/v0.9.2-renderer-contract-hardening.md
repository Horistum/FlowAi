# v0.9.2 Renderer Contract Hardening

## Summary

v0.9.2 adds renderer contract hardening for Jenkins, GitHub Actions and Tekton renderer inputs.

The package line adds `TargetRendererContractValidator` and integrates it into the main renderers so invalid renderer input is rejected before target artifact serialization.

## Added

- `TargetRendererContractValidator`
- `TargetRendererContractReport`
- `TargetRendererContractIssue`
- `TargetRendererContractValidatorTests`
- `docs/V0_9_2_RENDERER_CONTRACT_HARDENING.md`

## Changed

- `JenkinsManifestRenderer` now validates render input before serialization.
- `GitHubActionsManifestRenderer` now validates render input before serialization.
- `TektonManifestRenderer` now validates render input before serialization.
- Package and release metadata now target `0.9.2`.
- Roadmap state now marks `0.9.2` as completed and `0.9.3` as next.

## Contract coverage

The renderer contract validates:

- manifest contract results
- renderer target identity
- known job dependencies
- known job or step dependencies
- non-empty structural containers
- valid try body and handler shape
- no ambiguous command-plus-children steps

## Validation expectation

GitHub Actions or local review must run:

```bash
./gradlew --no-daemon clean test --stacktrace --console=plain
./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain
```
