# v0.9.5.7.5 Compatibility and Readiness Honesty

## Summary

This repair prevents capability compatibility from being reported as executable readiness for a concrete target manifest.

## Added

- `CompatibilityReadinessReport`
- `MaterializationReadinessStatus`
- `ProjectionReadinessStatus`
- `TargetCompatibilityReadinessAnalyzer`
- manifest compatibility reconciliation on canonical and safe projection paths
- readiness-aware execution, negotiation, selection and decision-trace reconciliation
- regression tests for review-only, fail-fast and executable manifests
- conformance checks that evaluate concrete Jenkins, GitHub Actions and Tekton manifest evidence before accepting readiness or target recommendations

## Result

- capability compatibility remains visible as platform-level evidence
- capability negotiation without a concrete manifest is explicitly preliminary and recommends no target
- effective compatibility is derived from materialization and projection evidence
- review-only artifacts cannot present capability-only `SUPPORTED` as their effective state
- blocked materialization becomes effectively unsupported
- target recommendations require executable supported manifests
- canonical target manifests store readiness metadata and an effective compatibility status
- decision traces cannot pass without a recommendation backed by executable renderer evidence
- readiness reconciliation is monotonic: concrete evidence may preserve or worsen a capability result, but cannot remove an existing blocker
- targets without a concrete manifest remain explicitly unevaluated rather than inheriting fabricated readiness evidence

## Validation

- `./gradlew --no-daemon clean test --stacktrace --console=plain` passed in Flow CI run `#781`
- `./gradlew --no-daemon run --args="conformance" --stacktrace --console=plain` passed in the same run
- the exact conformance alignment was applied before validation and persisted only after both commands passed
- the temporary validation patch, workflow and Gradle export finalizer were removed from the persisted branch state
- the final branch contains only production sources, tests, conformance updates, snapshots and documentation for this repair

## Validation boundary

The repair changes reporting and selection honesty. It does not add target payload implementations or make current reference scenarios executable.

## Version boundary

- package version remains `0.9.4`
- active public standard remains `0.7.6`
- target manifest schema remains `1.0`
- no runtime executor, SDK, framework lifecycle, shell generator or public target DSL is introduced
