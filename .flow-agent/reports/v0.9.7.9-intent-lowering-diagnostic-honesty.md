# v0.9.7.9 Intent Lowering and Diagnostic Honesty

## Status

Completed.

## Objective

Ensure every accepted meaningful intent input is either preserved through canonical lowering or rejected with explicit, stable and source-form-independent diagnostic evidence.

## Strict source boundary

`IntentYamlLoader` now validates the complete public intent shape. Unknown fields, invalid object and list shapes, non-string keys, invalid booleans, unsupported normalized values, unknown enums, empty references and duplicate nested or inline system configuration sources fail with an `IntentSourceException` containing a stable code, source path and source name.

Equivalent block-style YAML, flow-style YAML, JSON and normalized map inputs remain supported and produce equivalent intent documents. Source syntax no longer changes enforcement behavior.

## Lowering coverage

`IntentLoweringReport` records deterministic `sourcePath` to `targetPath` evidence with a `PRESERVED` or `TRANSFORMED` disposition and the canonical value kind. `IntentSourceMetadata` preserves descriptions, workflow identity, policy source, system purpose and failure declarations beside the semantic AST instead of allowing those values to disappear.

Declared outputs, source step identity and description, structured defaults, and explicit binding metadata survive through AST, ExecutionPlan and canonical plan projection. Structured defaults retain the canonical expression; the older scalar default remains only where the source is a string literal.

## Fail-closed boundaries

Unknown semantic parameters are errors unless `CUSTOM` explicitly owns them. Multiple independent workflows, `failure.stopOnError=false` and policy types without a canonical lowering contract are rejected rather than flattened or ignored. Empty and duplicate declared outputs are rejected.

`MandatoryMaterializationAuthority` validates lowering contract version, evidence uniqueness, evidence shape and exact source-step coverage before target provider invocation. A plan cannot omit or forge source lowering evidence and still claim executable readiness.

## Reference integrity

Both committed snapshot bundles were regenerated through `ReferenceSnapshotBundleGenerator`. The checkout-and-build reference remains explicitly Jenkins-only and executable. Other target readiness remains governed independently by capability, continuity, control and topology evidence.

## Version boundary

Package version `0.9.5`, next package line `0.9.6`, public standard version `0.8.0` and artifact contract version `2.0` remain unchanged. The execution-plan schema receives additive lowering metadata within the existing artifact contract.
