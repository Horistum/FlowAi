# v0.8.5 Runtime Input Environment Rendering

## Objective

Apply the renderer/snapshot part of the reviewed patch on top of the current GitHub `main` branch.

The change moves runtime Flow input references in generated shell command text away from direct target-specific parameter interpolation and into deterministic `FLOW_*` environment variables.

## Branch

`v085-runtime-input-env-rendering`

## Scope

Changed files:

- `src/main/kotlin/org/flowlang/generators/manifest/TargetManifest.kt`
- `src/main/kotlin/org/flowlang/generators/manifest/TargetManifestRenderers.kt`
- `src/test/kotlin/ReviewRegressionTests.kt`
- `tests/FlowSemanticCorrectnessHardeningTests.kt`
- `conformance/snapshots/build-test-deploy/Jenkinsfile`
- `conformance/snapshots/build-test-deploy/github-actions.yml`
- `conformance/snapshots/build-test-deploy/tekton-pipeline.yaml`

## Behavior

- `${input}` tokens inside command arguments render as shell-safe `"$FLOW_INPUT"` references.
- Literal command-argument segments remain POSIX single-quoted.
- Jenkins binds declared inputs at pipeline `environment` scope.
- GitHub Actions binds only referenced inputs at job `env` scope.
- Tekton binds only referenced inputs at step `env` scope.
- Existing target condition expressions still use each target's native expression language.

## Architecture boundary

This is still renderer/projection hardening only.

It does not add:

- a runtime executor
- an SDK API
- a plugin lifecycle
- target-specific public Flow syntax
- a public standard version bump
- an artifact schema version bump
