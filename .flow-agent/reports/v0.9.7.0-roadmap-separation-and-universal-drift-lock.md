# v0.9.7.0 Roadmap Separation and Universal Drift Lock

## Purpose

Prevent the Flow roadmap from mixing universal semantic development with concrete adapter coverage and conformance evidence.

The previous linear roadmap allowed implementation-oriented work packages to become the practical driver of Core design. This work item replaces that structure with separate planning authorities and mechanical drift checks.

## Outcome

The repository now has:

- a top-level roadmap index;
- a Core roadmap for universal semantic contracts;
- an adapter roadmap for concrete bindings, topology evidence and artifact generation;
- a conformance roadmap for cross-domain adequacy, topology behavior, equivalence and adapter certification;
- a historical roadmap for completed v0.7 through v0.9.6 work.

The primary Flow Agent work item is `0.9.7.1 Canonical Intent Meaning` from the Core stream. Other streams may maintain independent next-item state without redefining the primary Core direction.

## Mechanical enforcement

Flow Agent tooling now:

- requires the three active roadmap streams;
- rejects repository-external or duplicated roadmap paths;
- requires at most one `next` item per stream;
- requires one `next` item in the declared primary stream;
- requires every Core item to declare `universalInvariant`, `forbiddenScope` and `completionEvidence`;
- rejects concrete platform and implementation-tool names from Core item names, purposes and required outcomes;
- includes every active stream in generated agent context.

## Validation

The isolated tooling validation passed:

- nine roadmap parser and governance unit tests;
- split-roadmap structure validation;
- primary Core next-item resolution;
- negative cases for path escape, missing streams, multiple next items, missing Core governance fields and concrete implementation scope.

GitHub Actions **Flow CI #1520**, run `29560189402`, then passed the unmodified repository workflow on implementation head `08ee3947792cd703d54f4f270d7e83568685e509`, including Flow Agent tooling, structure validation, context generation, compile, full tests and full conformance.

The final validation-metadata-only head must also pass the same unmodified workflow before the pull request is marked ready for review.

## Architecture boundary

This work changes roadmap governance, Flow Agent tooling and documentation only.

It does not change:

- production Kotlin sources;
- Intent, AST, ExecutionPlan or manifest contracts;
- materialization or projection behavior;
- adapter capability coverage;
- conformance vectors;
- package, public standard or artifact contract versions.

No runtime executor, SDK lifecycle, plugin framework, raw runtime projection or concrete-platform semantic authority is introduced.
