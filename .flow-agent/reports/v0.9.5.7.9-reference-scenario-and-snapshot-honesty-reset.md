# v0.9.5.7.9 Reference Scenario and Snapshot Honesty Reset

## Purpose

Reset reference scenarios and snapshots so committed evidence states exactly what the real parser, planner, compatibility, materialization and render pipeline can prove.

## Implemented

- Active flagship examples use semantic `standard.execute` actions instead of `shell.run`.
- Historical shell examples remain isolated under `examples/migration/blocked-shell` and are required to fail before target projection.
- The canonical target-manifest pipeline rejects blocking compatibility evidence even when called directly outside the CLI.
- Reference projection outcomes are derived from core validation, target compatibility and concrete manifest/render evidence rather than target or scenario identifiers.
- Reference snapshot generation uses the real intent loader, validators, AST planner, Flow planner, compatibility analyzer, readiness analyzer, canonical manifest pipeline and render policy.
- Jenkins and GitHub Actions remain explicit `REVIEW_ONLY` evidence for the realistic build-test-deploy scenario.
- Tekton is recorded as `FAIL_FAST` diagnostic evidence with no target manifest and no emitted target YAML.
- Snapshot filenames and `snapshot-index.json` expose semantic-only, review-only, executable and fail-fast states explicitly.
- Conformance regenerates the complete snapshot bundle and compares committed files canonically.
- An isolated Jenkins `git.checkout` scenario remains the current executable proof. The realistic pipeline cannot borrow that executability.

## Native projection coverage boundary

Native projection coverage remains intentionally limited. Jenkins `git.checkout` is the isolated executable evidence currently covered by a concrete `NATIVE` projection rule and renderer payload. Actions such as `standard.execute`, Docker, Kubernetes, Argo CD and notifications remain notes-projected, adapter-required or unsupported according to their actual registry evidence.

Expanding native action-target payload coverage is separate work tracked under `0.9.7 Projection Rule Coverage`. This honesty reset does not manufacture renderer payloads or upgrade review-only scenarios merely to make snapshots look more complete.

## Version boundary

The historical correction identifier `0.9.5.7.9` is not a package, public-standard or artifact-contract version.

- implementation package: `0.9.5`
- public Flow standard: `0.8.0`
- Intent contract: `2.0`
- AST contract: `2.0`
- ExecutionPlan contract: `2.0`
- TargetManifest contract: `2.0`
- TargetRegistry contract: `2.0`

Every generated snapshot records these axes together. A fail-fast target has no TargetManifest instance, so manifest presence is recorded as false rather than implying a serialized artifact that never existed.

## Architecture boundary

This correction introduces no runtime executor, SDK, framework lifecycle, plugin lifecycle, shell generator, command projection or target-specific public Flow DSL.
