# v0.9.7.9.1 Evidence and Control Integrity Repair

## Status

Completed as a bounded correction slice. This report does not close the full v0.9.7 correction track.

## Why this correction was required

The previous v0.9.7.9 completion claim was not trustworthy. Standard Intent accepted `TEST.params.command`, canonical lowering removed the value, and the lowering report still labelled the source parameter as `PRESERVED`. The generated report therefore certified a property that was false in the produced artifact.

The same audit identified additional fail-open paths that belonged in the same first repair boundary:

- dynamic or unrelated approval evidence could authorize execution materialization;
- explicit source text such as `no backup` could synthesize a positive BACKUP step;
- module-declared capabilities and schema-valid Argo CD configuration were silently lost during planning;
- dead Core surfaces still implied target ownership or portable-shell behavior.

## Architectural decisions

### Runtime command text fails before lowering

Flow Core remains a target-neutral semantic standard. It does not preserve arbitrary command text as an opaque escape hatch. BUILD, TEST, PACKAGE and RUN_COMMAND now reject `command`; RUN_COMMAND requires a semantic description until a typed operation model exists.

### Approval evidence is task-scoped

An approval protects a task only when it is a dependency ancestor of that task. A safety declaration states a requirement but is not implementation evidence. Conditional or otherwise dynamic approval remains useful diagnostic evidence, but it blocks execution planning until provider enforcement evidence exists.

### Source contradictions fail closed

Normalized intent cannot override explicit negative source meaning. Backup denial is checked independently of scenario-pack heuristics, preventing the word `backup` inside a negative sentence from becoming positive safety evidence.

### Module descriptors drive planning requirements

`ModuleActionContract.requiredCapabilities` is consumed by the planner. System configuration is propagated from the declared system-type schema rather than module-name switches. Target support remains owned by target registries and provider catalogs.

## Implemented changes

- removed free-form command acceptance from standard runtime-oriented capability contracts;
- added focused command-boundary negative tests;
- bound approval evidence to dependency reachability;
- converted unresolved dynamic controls to execution-plan blockers while retaining diagnostic context;
- removed control-obligation deduplication that could hide ID collisions;
- added source contradiction validation for negative backup statements;
- made capability and system-config propagation descriptor-driven;
- added Argo CD propagation coverage for URL, symbolic secret token, `argocd.api` and `secrets.runtime`;
- removed the dead `targetImplications` model/report surface;
- removed the legacy portable-shell error-handler lowering overload;
- aligned schemas and conformance checks with the actual module authority;
- regenerated the complete build-test-deploy snapshot bundle through the canonical generator;
- separated conditional approval renderer coverage from the unconditional executable reference scenario.
