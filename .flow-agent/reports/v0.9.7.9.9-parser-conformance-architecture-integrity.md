# v0.9.7.9.9 Parser, Conformance and Architecture Evidence Integrity

## Status

The bounded correction is `complete`. Parent Core item `0.9.7.9` is restored to `completed`, and closure item `0.9.7.10` is the next Core item. Flow CI #2048 independently passed the implementation head and synthetic merge candidate. The completion-metadata head still requires the same dual workflow before pull-request review readiness.

## Why this correction exists

A post-completion audit found five bounded integrity defects:

1. the public `.flow` parser silently converted malformed `retry` values to defaults and discarded unknown policy fields;
2. standard compliance conformance supplied only a hand-built passing manifest, so it did not prove rejection behavior;
3. the serializer boundary inspected only five packages and missed a live Jackson annotation in the target-neutral projection contract;
4. module target-rendering governance depended on exact YAML indentation even though canonical module loading already owns structural validation;
5. universal evidence, draft, schema and decision checks unnecessarily obtained their Core plan through `buildPipeline("jenkins")`.

These findings reopened `0.9.7.9` because they directly violated its invariant that accepted information never disappears silently and because release evidence must be falsifiable rather than decorative.

## Implemented boundaries

### Fail-closed `.flow` retry parsing

`FlowParser.parseRetry` now:

- accepts defaults only when a field is omitted;
- requires integer numeric evidence for `retry.max`;
- requires text for `retry.delay`;
- requires text or a symbolic identifier for `retry.backoff`;
- rejects unknown keys with a `retry.<key>` path;
- rejects duplicate keys instead of allowing later values to overwrite earlier authored meaning.

Regression tests cover valid preservation, type errors, fractional attempts, unknown fields and duplicate fields.

### Falsifiable compliance evidence

`StandardEvidenceChecks` now feeds `StandardComplianceAnalyzer` both a passing and a failing conformance manifest. It asserts:

- passing evidence produces `PASS`;
- failing evidence produces overall `FAIL`;
- `failedGates` contains `conformance.pass`;
- the public standard draft also remains `FAIL` when supplied failing compliance.

The gate therefore proves both acceptance and rejection behavior instead of certifying only a prepared passing fixture.

### Semantic serialization boundary

The Jackson annotation was removed from `ProjectionBinding`. Null omission remains an infrastructure concern of the configured JSON mapper and is protected by a structural serialization regression test.

Architecture checks and tests cover the complete declared semantic package set rather than five selected directories. The boundary includes intent, effects, controls, topology, lowering, modules, validator, semantic, materialization, projection, notes, identity and safety contracts in addition to the original packages.

### Canonical module authority

The indentation-based regular-expression scan was removed from conformance. Shipped descriptors are loaded through `CanonicalModuleLoader`, and negative tests prove that action-owned `runtime`, `generators`, `template`, `entrypoint` and `targetImplications` fields fail under varied YAML forms. Legitimate input fields named `template` remain accepted because the rule is structural, not textual.

### Target-neutral universal conformance

`TargetNeutralConformanceFixture` builds intent, AST, validation and execution-plan evidence without selecting a projection. Target diagnostics are aggregated across the registered target inventory only for reports that explicitly model target compatibility.

The following checks now use this target-neutral substrate:

- artifact evidence, integrity, contract index, compliance, freeze and public draft;
- public schema validation for Core artifacts;
- target decision and public artifact bundle checks.

Concrete Jenkins evidence remains in checks that genuinely validate Jenkins manifests or rendering. The correction does not optimize platform-name counts; it separates ownership boundaries.

### Generic bounded-correction release authority

The audit-driven implementation exposed a sixth adjacent defect: `ReleaseMetadataHonestyAuthority` hard-coded `0.9.7.9.8`. It now selects the active work package from roadmap state and, after completion, selects the newest bounded `0.9.7.9.x` work package. CLI and closure conformance validate the bounded correction track rather than one historical identifier.
