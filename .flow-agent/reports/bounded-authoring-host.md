# Bounded external authoring host

AI-A3 begins from merged AI-A2 PR #256 at `81180222b0cf14867f468e8ff3dfffb0ca75aaa7`.
Baseline [Flow CI](https://github.com/Horistum/FlowAi/actions/runs/42196093837) and
[Adapter Runtime Certification](https://github.com/Horistum/FlowAi/actions/runs/42196093990) passed.
This is an implementation candidate, not a completed real-model milestone. The final
PR validation record owns exact-head and merge-candidate CI receipts.

The standalone Python host reuses the command-reasoning/v2 provider protocol from
`gitops-agent-control-plane` without importing its delivery/execution controller.
It invokes the installed product for all semantic, request-fidelity and target
decisions. Complete replacements, immutable original requests, separately reviewed
expectations, durable dispatch reservations, explicit clarification and conservative
stop states form the review boundary. It introduces no compiler model dependency,
runtime workflow execution, database, target-specific syntax or adapter workaround.

The frozen corpus runner requires at least three repetitions with fixed settings
and an explicit suite budget/target. Independent expectations and expected proposals
remain outside model prompting and repair. Descriptive metrics separate acceptance,
fidelity, unsupported cases, clarification, latency and cost. Independent quality
review is mandatory and cannot be self-certified by the runner.

Offline process tests cover valid repairs, unchanged proposals, independent budget
caps, interrupted/uncertain attempts, provider identity/usage violations, credential
isolation/redaction, explicit clarification, stale evidence, target blocks and corpus
integrity. Installed-product verification exercises actual compilation, a hard
constraint mutation, clarification continuation and all twelve corpus cases three
times with a deterministic peer. Those repetitions are integration tests, not live
model evaluations. Required CI adds the installed-host verification to exact-head
and merge-candidate jobs while retaining physical product isolation.

Live evaluation is pending an explicitly configured provider/model/access and
approved operating limits. The fully specified held-out certificate case is accepted
canonically and satisfies its independent requirements, but Jenkins rendering is
review-only (`CLI_RENDER_NOT_AUTHORIZED`). This is a concrete open target prerequisite,
not a missing user answer or faithful executable result. No live-quality numbers or
full AI-A3 completion are claimed.

The coordinated route selects AI-A3 while replaying AI-A2, AI-A1 and every earlier
recovery acceptance gate. AR-06 remains active, full AR-07 remains planned with its
AR-06 dependency, F-16/F-20 retain their closure owners and EF-09 remains paused.
AI-A3 closes only after the original live corpus, per-domain, hard-constraint,
clarification/unsupported-quality and held-out executable-render gates are met.
