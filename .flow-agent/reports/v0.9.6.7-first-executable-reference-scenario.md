# v0.9.6.7 First Executable Reference Scenario Report

## Purpose

Add the first committed realistic multi-step executable reference evidence without widening native action claims or weakening unresolved scenarios.

## Selected scenario

`checkout-build-image` contains:

1. checkout of `https://github.com/octocat/Hello-World.git` on branch `main`;
2. build of `ghcr.io/flowlang/reference:${version}` from the checked-out root workspace;
3. `push: false`, avoiding invented registry authentication.

## Target scope

The executable proof is scoped to Jenkins.

Jenkins preserves both actions as ordered steps in one generated stage and workspace. The resulting target artifact uses the reviewed native Git step followed by the Docker Pipeline `docker.build()` object API.

GitHub Actions is excluded because the current generator creates separate jobs without explicit workspace transfer. Tekton is excluded until a complete PipelineRun workspace binding is part of committed reference evidence. Individual native action support for those targets is unchanged.

## Evidence path

The snapshot is generated through:

- Intent YAML loading;
- intent capability validation;
- Intent-to-AST planning;
- Flow AST validation;
- ExecutionPlan generation;
- compatibility and readiness analysis;
- native materialization and typed payload compilation;
- Target Manifest generation;
- executable render policy;
- Jenkins serialization.

No snapshot field is edited to declare executable state manually.

## Honesty preservation

The existing `build-test-deploy` scenario remains MIXED and non-executable. Its standard test, approval, deploy, verify, rollback and notification operations are not relabeled or removed.

## Tests

Coverage verifies:

- exactly two ordered plan tasks, `git.checkout` then `docker.build`;
- repository, image, version interpolation and no-push policy preservation;
- supported Jenkins compatibility and generation readiness;
- complete native materialization and executable render mode;
- one Jenkins job with checkout before image build;
- absence of review artifacts, shell steps and Docker CLI projection;
- canonical committed bundle equality file for file;
- target-scoped snapshot state containing only executable Jenkins evidence;
- continued MIXED state of `build-test-deploy`.
