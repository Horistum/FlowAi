# v0.9.6.5 Cross-target Checkout Report

## Purpose

Add honest native `git.checkout` projection coverage across selected built-in targets using the provider-owned architecture from v0.9.6.4.

## Implemented coverage

### Jenkins

- Payload: `JENKINS_STEP/git`.
- Bindings: `url`, `branch`, optional `depth`.
- Depth `0` preserves the native full-history `git` step.
- Positive depth uses structured Git SCM checkout with `cloneOption`.

### GitHub Actions

- Payload: `GITHUB_ACTION/actions/checkout@v4`.
- Bindings: Flow `url` to action `repository`, `branch` to `ref`, and `depth` to `fetch-depth`.
- The renderer accepts HTTPS, SSH, Git or SCP-style references only when they identify a `github.com` owner/repository pair.
- Other hosts fail closed instead of producing an invalid action input.

### Tekton

- Payload: `TEKTON_TASK/git-clone`.
- Bindings: `url`, `revision`, `depth`, and typed task-target metadata for workspace identity.
- The Pipeline declares each required checkout workspace.
- The git-clone Task binds its `output` workspace to the declared Pipeline workspace.

## Shared semantic contract

All selected targets preserve repository URL, branch and depth. Depth `0` represents full history; positive values represent shallow checkout. Non-numeric or negative values are rejected by the concrete target edge.

No target syntax or repository parsing is added to Flow Core.

## Unsupported targets

Targets without both registry evidence and a provider-owned checkout contract remain `ADAPTER_REQUIRED` or review-only. Coverage is not inherited merely because another platform has a similar checkout primitive.

## Tests

Coverage verifies:

- registry, provider catalog and renderer agreement for all three targets;
- the source-language parser, validator and planner carrying `git.checkout` capability evidence;
- executable readiness through the real compatibility and manifest pipeline;
- Jenkins full and shallow checkout rendering;
- GitHub repository normalization, branch and fetch depth;
- Tekton params and required workspace structure;
- fail-closed behavior for non-GitHub repository URLs and invalid depth;
- adapter-required behavior for an unimplemented target;
- canonical execution-plan snapshot alignment after the planner capability evidence change.
