- `SafetyBoundaryValidator` was optional and absent from `FlowValidator`.

## Implemented design

### Typed environment evidence

Environment parameter evidence is represented as a literal, reference or dynamic expression. A reference remains a reference and retains its path only as diagnostic evidence.

The standard policy evaluates only names declared by its rules. Explicit environment fields such as `environment`, `env` and `stage` fail closed on unmatched literals. Contextual namespace or cluster identifiers require an actual policy match before they become environment claims, so arbitrary resource names are not guessed safe or production-sensitive.

### Scoped approval evidence

Unconditional approval is sequential and does not leak out of optional control-flow branches. A conditional approval is accepted only as an environment guard when its predicate is structurally proven to select a policy-declared sensitive value, such as `environment == "prod"`. It never authorizes unrelated destructive work.

An action-local `safety: requiresApproval` must be unconditional. Arbitrary `onlyIf` text is not approval evidence.

### Finite non-sensitive environment proof

Destructive `onlyIf` safety is accepted only when the referenced input has a finite option domain and exhaustive evaluation proves every value for which the action may execute is policy-classified `NON_SENSITIVE`. A guard such as `environment != "prod"` over `dev`, `test` and `prod` is therefore provable. A generic boolean such as `allowDelete == true` remains insufficient.

### Authority composition

Canonical Intent rollback actions remain governed by typed Intent control evidence. Directly authored raw Flow rollback actions retain the local approval requirement, while rollback in an error handler remains allowed.

`FlowValidator` owns production composition of structural and safety validation. CLI lowering requires a valid Flow report before invoking `FlowPlanner`. Reference snapshot generation uses the same composed validator.

## Diagnostics

The standard diagnostic catalog now registers:

- `APPROVAL_REQUIRED`
- `ROLLBACK_APPROVAL_REQUIRED`
- `ENVIRONMENT_APPROVAL_REQUIRED`
- `ENVIRONMENT_CLASSIFICATION_UNKNOWN`

The existing `SAFETY_REQUIRED` code remains stable for destructive actions without explicit safety evidence.
