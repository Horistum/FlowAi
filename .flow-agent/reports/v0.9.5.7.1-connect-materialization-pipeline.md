# v0.9.5.7.1 Connect Materialization Pipeline

## Summary

This repair step connects real execution-plan tasks to the notes, semantic action graph, materialization negotiation and projection plan model before target manifest emission.

The previous manifest boundary used a local hardcoded materialization switch. This PR replaces that path for task steps with `TargetMaterializationResolver`.

## Added

- `TargetMaterializationResolver`
- `TargetMaterializationResolution`
- `FlowConnectedMaterializationPipelineTests`
- `.flow-agent/roadmap-v0.9.5.7-repair-track.yaml`
- `docs/V0_9_5_7_1_CONNECT_MATERIALIZATION_PIPELINE.md`

## Changed

- `TaskNode.toTargetStep()` now resolves action materialization through the connected resolver.
- Action steps carry semantic graph, negotiation and projection artifact metadata.
- `standard.execute` and `standard.rollback` can now reach `NOTES_PROJECTED` status only through generated capability notes and explicit materialization evidence.
- Adapter-required actions remain non-executable but now carry auditable projection evidence.
- Raw runtime action intent remains blocked at the projection boundary instead of being treated as target execution.

## Validation focus

The tests verify that:

- notes-backed materialization is reachable through a real task resolution path,
- adapter-required actions carry semantic negotiation and projection artifact evidence,
- blocked runtime action intent remains preserved as a review record,
- manifest generation uses resolver metadata rather than only a local switch.
