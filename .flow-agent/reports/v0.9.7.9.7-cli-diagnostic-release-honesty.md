# v0.9.7.9.7 CLI Diagnostic and Release Honesty

## Status

Implementation complete. Exact-head Flow CI validation is pending and remains external pull-request evidence.

## Scope

This correction covers the public CLI, target render authorization, per-flow artifact export, standard release assembly, bundle publication and release metadata reconciliation.

## Defects confirmed before implementation

- A known target provider was rendered even when `--render` was absent.
- `--out` could persist rendered target syntax without an explicit render request.
- Capability-only readiness, selection and decision trace artifacts were exported beside a concrete target manifest.
- `TARGET MANIFEST READY` conflated structural manifest generation with executable render readiness.
- Adapter contract diagnostics were not updated from concrete manifest evidence.
- Standard draft construction used a synthetic `ADAPTER_CONTRACT_READY` diagnostic.
- Standard compliance considered absent conformance evidence non-failing.
- Standard export wrote directly to the destination before final conformance and verification.
- Release state, roadmap, report and correction history disagreed about the active work item and validation evidence.
- Runtime-required diagnostics implied that Flow Core supplied runtime support.

## Implementation summary

### CLI evidence

`CliTargetEvidenceAuthority` now:

1. computes preliminary target facts;
2. generates one manifest through the supplied projection registry;
3. reconciles negotiation, readiness and selection against that exact manifest;
4. builds a decision trace from reconciled reports;
5. derives adapter diagnostics from concrete readiness;
6. evaluates render readiness;
7. invokes the renderer only after explicit request and executable authorization.

### CLI entrypoint

The Gradle application now routes through `org.flowlang.cli.honest.HonestFlowCliKt`.

Release-facing and intent-lowering commands no longer use the legacy optimistic command path. Legacy commands not included in the correction remain delegated for compatibility.

### Artifact export

Per-flow bundles are constructed from the actual emitted artifact set. Rendered files are declared only when a renderer was explicitly requested and authorized.

### Release compliance

`StandardComplianceAnalyzer` now requires an explicit conformance manifest with status `PASS`. Missing evidence is reported as `NOT_PROVIDED` and fails `conformance.pass`.

### Release assembly

`StandardReleaseAssemblyAuthority` uses:

- real conformance summary and manifest;
- vector-index consistency;
- release metadata honesty;
- artifact integrity;
- explicit artifact provenance;
- contract index and freeze;
- compliance and public draft reports.

Every required JSON artifact declares an existing schema.

### Publication

`standard-export` writes to a sibling staging directory, verifies the staged bundle and only then replaces the destination. Existing output is backed up and restored if replacement fails.

### Metadata

`ReleaseMetadataHonestyAuthority` distinguishes:

- package `0.9.5`;
- next package `0.9.6`;
- public standard `0.8.0`;
- completed correction item `0.9.7.9.7`;
- next Core item `0.9.7.10`.

The candidate commit cites only the last merged validation, Flow CI #2001 on the final v0.9.7.9.6 head. Candidate CI success is not predeclared.

### Runtime wording

Public compatibility and readiness diagnostics now state that runtime-required capabilities depend on external target-side infrastructure or adapters and that Flow Core provides no runtime.

## Tests and conformance

Added tests cover:

- no renderer file without `--render`;
- reconciled readiness in exported artifacts;
- review-only render rejection before output publication;
- missing conformance evidence failing release compliance;
- release metadata axis consistency.

Added conformance check:

```text
cli.release.diagnostic-honesty
```

It verifies the public entrypoint, reconciled target evidence, explicit render authorization, release metadata, staged verification order and runtime wording.

## Version boundary

No package version, public standard version or existing artifact contract version is promoted.

A new additive report schema is introduced:

```text
schemas/release-metadata-honesty-report.schema.json
```

The schema describes release metadata evidence; it does not redefine any existing standard artifact.

## Architecture boundary

No runtime execution, SDK lifecycle, plugin discovery, target command transport, shell projection, implicit renderer invocation or automatic publication is introduced.
