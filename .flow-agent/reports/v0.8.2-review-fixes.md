# v0.8.2 Review Fixes

## Review triage

This review separates confirmed defects from broader design observations.

## Fixed in this branch

- Recent package-line checks are now recorded in `StandardModel` as package-level checks outside the public release profile. This keeps the public release profile stable while making the post-0.7.5 package line visible to the standard model.
- The roadmap marks v0.8.2 as completed and keeps v0.8.3 as the next item.

## Confirmed but deferred

- Built-in module descriptions are still backed by hardcoded defaults. The preferred fix is to either load `modules/*.yaml` as production descriptors or remove the duplicated YAML definitions after hardcoded descriptions are made authoritative.
- GitHub Actions list-literal condition rendering should emit valid JSON for `fromJSON`. The source update was blocked by the current connector because the file contains GitHub expression syntax.
- Built-in target registry top-level description is stale and should be updated in a small local patch.
- Top-level historical validation documents should be replaced with current package-line summaries.

## Design observations left for separate work

- Error-handler rendering through the manifest path needs a dedicated semantic fix.
- Intent lowering currently serializes ordered steps. This is a safe default, but should be documented before DAG-parallel lowering is introduced.
- Data operation result dependencies and legacy direct generators need separate design cleanup.
- JSON schema id/domain normalization should be handled as a schema-governance task.
