# v0.9.5.1 Shell Usage Inventory and Prohibition

## Summary

v0.9.5.1 records the shell and command-oriented projection inventory after the architecture recenter and applies the first removal gates.

Flow Core no longer generates raw command text as the TargetManifest execution truth. Generated action steps carry structured materialization status and renderers refuse to invent shell, script or run blocks as a default projection.

## Corrected areas

- `TaskNode.toTargetStep(...)` now attaches `TargetMaterialization` instead of generated command text.
- `runCommandFor(...)`, `PORTABLE_ACTIONS`, shell quoting helpers and semantic echo materialization were removed from the manifest generator path.
- Jenkins rendering no longer emits `sh(script: ...)` for generated Flow actions.
- GitHub Actions rendering no longer emits `run: |` blocks for unmapped generated Flow actions.
- Tekton rendering no longer emits `script: |`, `#!/bin/sh` or generated shell bodies.
- Intent lowering no longer maps BUILD, TEST, PACKAGE or low-level runtime requests to `shell.run`.
- Standard capability contracts and catalog entries no longer treat shell as the default build/test/package/runtime module.
- The legacy `TargetStep.run` compatibility field is rejected by the manifest contract when populated.

## Remaining classification

The following are still classified as legacy or follow-up architecture areas, not universal Flow semantics:

- compatibility references to `TargetStep.run`
- CI/CD-specific tool assumptions such as Docker, Kubernetes, Argo CD and registry defaults
- scenario-pack deployment conventions around Kubernetes, Docker registry and pod verification
- concrete target materialization before notes packages declare the required runtime behavior

These are intentionally carried into the next v0.9.5.x correction items rather than hidden as successful target work.

## Prohibition

New Flow Core changes must not add command-oriented mappings, echo-success placeholders, shell/script renderer surfaces or hardcoded concrete-tool defaults as universal behavior.

Any future compatibility path must be explicitly marked as legacy, degraded, semantic-only, adapter-required or blocked until notes-driven materialization exists.

## Validation additions

- Added regression coverage that build/test/package intent lowering produces semantic `standard.execute` actions.
- Added regression coverage that verify lowering remains structured and does not synthesize shell actions.

## Versioning boundary

- Current package version remains `0.9.4`.
- Active public standard version remains `0.7.6`.
- This is roadmap correction work inside the v0.9.5.x correction track.
- No artifact schema version is changed.
- No runtime executor, SDK API, plugin lifecycle, target-specific public DSL, renderer expansion or Flow syntax change is introduced.
