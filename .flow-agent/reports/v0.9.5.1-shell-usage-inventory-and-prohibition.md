# v0.9.5.1 Shell Usage Inventory and Prohibition

## Summary

v0.9.5.1 records the initial shell and command-oriented projection inventory after the architecture recenter.

This change does not remove legacy behavior yet. It classifies known shell, command string, CLI and echo paths as legacy defects that must be corrected through the v0.9.5.x track.

## Confirmed inventory areas

- `TargetManifest.run`
- `TaskNode.toTargetStep(...).run = runCommandFor(...)`
- `PlanNode.toTargetSteps(targetName = "portable-shell")`
- `PORTABLE_ACTIONS`
- `runCommandFor(...)`
- `standardExecuteCommand(...)`
- renderer `sh`, `run`, `script`, `toShellLines` and echo fallback paths
- intent lowering defaults for Maven, Docker, Kubernetes, Argo CD and standard semantic echo behavior
- scenario pack deployment defaults for Kubernetes, Docker registry, Maven test and pod verification

## Classification

All command-oriented projection paths are legacy defects, not universal Flow semantics.

All semantic-only echo paths must become `SEMANTIC_ONLY` materialization once materialization negotiation exists.

All concrete tool defaults must move out of universal lowering and into notes-driven projection or explicit unresolved decisions.

## Prohibition

New Flow Core changes must not add new command-oriented mappings, new echo-success placeholders or new hardcoded concrete-tool defaults as universal behavior.

## Versioning boundary

- Current package version remains `0.9.4`.
- Active public standard version remains `0.7.6`.
- This is roadmap correction work inside the v0.9.5.x correction track.
- No artifact schema version is changed.
- No runtime executor, SDK API, plugin lifecycle, target-specific public DSL, renderer expansion or Flow syntax change is introduced.
