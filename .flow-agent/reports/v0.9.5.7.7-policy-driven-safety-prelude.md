# v0.9.5.7.7 Policy-Driven Safety Prelude

## Purpose

Remove validator-owned production string guessing and unconditional GitHub Actions production-environment projection before the wider policy-driven safety milestone.

## Implemented

- added environment safety policy notes, rules and classification evidence
- connected the baseline policy to the existing `flow.safety.core` notes contract and its declared package version
- replaced `SafetyBoundaryValidator` production parameter/value lists with supplied policy evidence
- preserved destructive, contract-required and rollback approval behavior
- added target-neutral approval-environment evidence resolution over downstream manifest parameters
- removed unconditional `environment: production` from the GitHub Actions renderer
- required sensitive, unique and policy-declared evidence before emitting a GitHub approval environment
- kept non-sensitive, unknown, missing and ambiguous environment evidence unprojected
- added regression coverage for baseline, custom, sensitive, non-sensitive and unknown classifications
- advanced the repair track to `0.9.5.7.8 Target Expression and Unknown Target Safety`

## Evidence boundary

Environment classification records:

- policy package and version
- matched rule
- matched parameter and value
- sensitivity
- optional approval environment
- decision reason

The policy does not execute runtime discovery or claim that parameter names are universally meaningful. The initial baseline preserves existing production-like aliases as declared policy data, not validator truth.

The correction identifier `0.9.5.7.7` is not used as a notes package version. Evidence uses the version declared by the `flow.safety.core` notes contract.
