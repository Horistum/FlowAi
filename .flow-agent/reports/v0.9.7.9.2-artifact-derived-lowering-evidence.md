# v0.9.7.9.2 Artifact-Derived Lowering Evidence

## Status

Implementation complete. Final exact-head validation is pending.

## Problem corrected

The previous lowering report was generated by iterating the source intent. It assigned target paths from list positions and marked fields as preserved without dereferencing the generated AST or execution plan. A field could therefore be dropped, reordered or changed while the report remained structurally valid.

## Implemented design

### Stable source catalog

`IntentLoweringAuthority.sourceMetadata` creates semantic source identities and expected target identities while the structured intent is available. Source list positions remain only in human-readable diagnostic paths.

### Shared value conversion

`IntentValueExpressionLowering` is used by both real AST lowering and evidence expectation construction. This prevents the evidence path from inventing a second interpretation of structured values, references, expressions or interpolation.

### Plan-derived report

IntentToAstPlanner does not issue a report. FlowPlanner first creates the complete execution plan and then invokes `IntentLoweringAuthority.report` against that plan.

The authority resolves every target identity, hashes the concrete value and enforces the declared disposition:

- `PRESERVED` requires source and target digest equality.
- `TRANSFORMED` requires a named transform and the expected transformed digest.

### Mandatory re-verification

The execution-plan materialization validator validates catalog uniqueness and coverage, re-resolves target values and requires exact equality with a newly derived report.

### Removed false evidence paths

- removed index-based target paths as authority
- removed source-generated lowering reports
- removed `dropBlockedParams`
- removed the synthetic notes-driven projection marker

## Contract change

ExecutionPlan remains `2.0`.

The embedded lowering evidence contract advances to `2.0` with:

- stable source and target identities
- source and target value digests
- explicit transformation names
- artifact kind
- aggregate `evidenceDigest`

The digest covers the certified evidence view. It is not represented as a hash or signature of the entire execution plan.

## Tests
