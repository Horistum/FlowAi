# v0.9.7.9.6 Derived Model and Governance Integrity

## Status

Implementation complete. Exact-head Flow CI validation is required before review readiness and is recorded on the pull request review surface.

## Confirmed failures

- negotiation summary fields could diverge from target support evidence
- target selection buckets and recommendations could be mutated independently from candidates
- decision traces could combine artifacts from different plans, strictness modes or target sets
- duplicate target manifests were silently collapsed by `associateBy`
- readiness-aware reports could be reused as preliminary reconciliation input
- the drift catalog could omit known signals, assign non-negative risk weights or weaken the threshold
- a free-text ADR phrase could mark an exception as recorded without naming the active signal or proving a conformance guardrail
- governance status and score fields were not independently checked against their detailed evidence

## Implemented authority

`DerivedModelIntegrityAuthority` validates negotiation, selection and trace composition. `ExecutionReadinessIntegrityAuthority` validates readiness summaries. Every production analyzer and reconciliation path now invokes these authorities before returning a public report.

Reconciliation is one-way. It accepts preliminary evidence only and rejects duplicate or out-of-scope manifest targets.

`ArchitectureGovernanceIntegrityAuthority` strictly validates the executable drift catalog and the report derived from it. `GovernedArchitectureAnalyzer` is the conformance and release-facing boundary that composes repository scanning with integrity validation.

## Governance exception model

An ADR exception must explicitly declare known negative signal ids and an existing conformance guardrail path. Unstructured text cannot waive governance findings.

## Verification coverage

Tests and conformance cover:

- valid preliminary and reconciled negotiation/selection reports
- mutated selection summary buckets
- forged capability-only recommendations
- mixed-plan decision trace inputs
- duplicate manifest target evidence
- repeated reconciliation of readiness-aware reports
- repository governance catalog and report consistency
- missing negative signals
- positive negative-signal weights
- weakened minimum thresholds
- unstructured ADR waiver text
- conformance gate `governance.derived-model-integrity`

## Architecture boundary

The change validates derived facts; it does not create a second planner, selector, governance scanner or target algorithm. Primary evidence remains authoritative. Package, public standard and artifact contract versions remain unchanged.

## Build discipline

All implementation, tests, documentation and conformance changes are assembled before opening the draft pull request. Flow CI is run only on the complete candidate or on a concrete correction head exposed by that build.
